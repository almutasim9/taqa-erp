# شمس ERP — بنية النظام

## الحدود المعمارية

`app/` للعرض والتفاعل فقط. `lib/financial/` خدمات نقية قابلة للاختبار. إجراءات الخادم تستدعي RPC في PostgreSQL لتنفيذ الدفعة، تخصيصاتها، السند، دفتر الأستاذ، وAudit Log ضمن معاملة واحدة. Supabase Auth يعرّف المستخدم؛ RLS لا يثق بالواجهة أبداً.

## قواعد مالية أساسية

- كل مبالغ IQD تخزن كـ `BIGINT`، ولا تستخدم Float.
- الدفعة لا تعدّل سجلاً مالياً معتمداً؛ التصحيح يتم بعكس (`reversal`) أو تعديل (`adjustment`).
- الرصيد والمبالغ المتاحة تحسب من ledger/allocations، وليست حقولاً يدوية.
- العقد يحتفظ بنسخة اتفاق الممول عند اعتماده.
- إعادة الجدولة تؤرشف فقط الأقساط غير المدفوعة في نسخة schedule جديدة؛ لا تمس الأقساط المدفوعة.

## الصلاحيات

المدير يمتلك جميع الصلاحيات. المحاسب يمنح permissions منفصلة مثل `customers.create`, `invoices.create`, `payments.create`, `expenses.create`; بينما `payments.reverse`, `contracts.reschedule`, `financier.settle`, `audit.read` و`users.manage` صلاحيات حساسة للمدير افتراضياً.
